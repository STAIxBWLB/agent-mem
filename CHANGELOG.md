## Unreleased

- **Versions coexist on one machine** (#199, change 6 and AC4-AC5). `amem manifest --json` prints `{ name, version, mcp: { server, tools }, commands }`; a tool is a plain name, or `{ name, readOnly: true }` for the nine read-only MCP tools, so an installer can grant a new read-only tool without a new release of its own (dotfiles#320). `amem setup <target> --root <abs path>` registers the hooks and MCP server (and, for `console`, the acon plugin) of that install root, resolved to its real path, such as `<install>/releases/<version>/`; the root must hold `package.json` named `@staix/agent-mem` and `bin/amem.js`, and without `--root` nothing changes. `amem mcp` loads every module its handlers can load lazily at start, so a release replaced under a running server never mixes two versions in one process. The derived curated index is named per `INDEX_VERSION` (`indexFileName`): version 3 keeps `index.db` and `index-v2.db`, and a later version builds its own file instead of dropping another version's. A person can append `{ surface, minReader, since }` records to `formats.json` in the memory home; a release below a floor refuses that surface (`curated`, `capture`, `hook-spool`, `candidates`, `work-lists`, `sync`, or `home` for all) with `code: "format_floor"` before it writes anything, and hooks below it capture nothing without denying. amem never writes the file.
- **Compatibility with N-1 (0.18.0):** hook spool, unchanged (format 2, as 0.18.0 writes and drains); shards, unchanged; candidates, unchanged; indexes, unchanged names and `INDEX_VERSION` 3, so 0.18.0 and this version share one warm index (`test/index-per-version.test.ts`); sync, unchanged. 0.18.0 does not read `formats.json`, so a floor binds only this version and later ones, and its `amem setup` has no `--root` (a root registered here stays until changed).

## 0.18.0

- Setup recognizes Orca-managed Claude/Codex homes and writes the durable personal source, preserving profile Claude MCP and byte-exact undo. Doctor reports applied-registration/path drift and missing Codex hook trust records without configuration contents; setup never grants hook trust (#202).
- Claude tool capture prepends a deterministic, screened tool-input line (512 UTF-8 bytes, within the total excerpt cap). Selected-project capture recall refills the existing capture slots with a fixed conversational-event weight and one best row per session, preserving the curated cohort; timeline/show retain every row. Capture schema and existing rows are unchanged (#196).
- **Console Recap panel** (#194). On demand, shows the selected project's current SessionStart context with screened coverage, partial status, conservative token bound and generation time. It is a fresh machine-policy read from private scratch, not a stored copy of a previous session's injected brief; no repository section is available in the console and no hook output or capture data is added.
- **Hook-spool records survive older versions on one home** (#199, P0 of the staged-upgrade contract). Staged hook records are format 2 (`schema: "agent-mem.hook-capture"`, `format: 2`) under `hook-v2-<cwd>-<scope>-<nonce>.json`, a name 0.14.0-0.17.0 do not match, so their drain and maintenance leave them alone instead of deleting them; this version still drains v1 records. A record with a valid envelope and an unknown or newer schema stays pending until the seven-day TTL and then retires with the counted reason `unknown_schema_expired`; a corrupt record is retired at once as before. `CandidateStore` skips a stored row of an unknown kind and counts it in `skippedUnknownKinds` instead of throwing. Development: `@staix/agent-mem-v017` pins the published 0.17.0 for the compatibility test (`test/hook-spool-compat.test.ts`).
- **Compatibility with N-1 (0.17.0):** hook spool, 0.17.0 ignores format-2 files (it still counts them toward its 256-file / 2 MiB cap) and this version drains 0.17.0's v1 records; shards, unchanged; candidates, unchanged storage and no new kind written, so 0.17.0 reads every row this version writes; indexes, unchanged; sync, unchanged.

## 0.17.0

- **Console plugin for acon** (#158). `@staix/agent-mem/ui-plugin` is an agent-console api 1 plugin: a Memory area with Review, Search, Timeline, Work lists, Goals and Capacity panels, inbox items for pending candidates and a capture capacity proposal, and palette search. Reads use the screened MCP read handlers in process (console search equals `amem_search` for the same query); the review queue and goals pass the configured policy and hide what fails it. No storage format, MCP tool or hook changes.
- Development: `@staix/agent-console` is a dev dependency pinned to a GitHub commit, for the contract types and the conformance suite; `src/` still imports no package.


## 0.16.0

- **Session and subagent attribution in capture** (#173, PR #181). Hook capture stores a 16-hex hash of Claude Code's `session_id` (never the raw id or transcript path) and `subagent: true` when the payload carries `agent_id`. The SessionStart brief and `sessionStartBrief()` skip subagent rows; search, timeline and show keep them. The capture shard gains two nullable columns on writable open; FTS bodies, curated schemas, hashes and sync are unchanged.
- **Compatibility (#173):** every amem hook binary that writes into one memory home (agent-hub pins included) must run 0.16.0 or later; upgrade them together. A 0.15.0 hook that drains a hook-spool record staged by 0.16.0 deletes it without reading or counting it, so a mixed or downgraded setup loses those pending captures. The 0.15.0 reader still opens and appends to an upgraded capture shard. Details in `docs/contracts.md`.
- SessionStart on `resume` emits only the untrusted-data header line, plus the capture-drop notice when there is one, and no brief body; the earlier brief is already in the restored transcript. `startup`, `clear`, `compact` and a missing or unknown `source` keep the full brief. `amem brief`, `sessionStartBrief()` and MCP are unchanged (#172, PR #179).
- **Overlap hints for pending candidates** (#174, PR #180). `amem review list --json` adds `overlaps` (up to three current same-project notes with id, title and score), `amem review walk` prints one line per overlap, and the `amem_remember` receipt adds an `overlaps` array of note ids. Hints use consolidation's word-overlap measure, are computed on demand, are screened by current policy and never merge, reject or block a candidate.
- **`amem setup opencode` and `amem setup gemini`** (#176; PRs #183, #184). They register the amem MCP server in OpenCode's global `opencode.json` (`mcp.amem`, verified with OpenCode 1.18.35) and in Gemini CLI's user `settings.json` through the native `gemini mcp add --scope user` (verified with Gemini CLI 0.61.0), with the existing preview/apply/undo receipts. `setup all` includes both. MCP only, no hook or ingest: neither client's transcripts carry message origin (`docs/opencode.md`, `docs/gemini-cli.md`). Antigravity's `~/.gemini/config/mcp_config.json` is never touched.
- `amem import codex` also reads the Codex memories v2 layout (`$CODEX_HOME/memories_v2/`, the default for fresh Codex 0.165.0 profiles) under the same bounds, symlink refusal and screening; v2 titles carry a `memories_v2/` prefix and v1 titles are unchanged. When neither location exists the receipt names both (#177, PR #182).
- **Purge procedure for a leaked secret or personal data** (#175, #188; PRs #187, #190). `docs/purge.md` is the person's procedure (rotate, forget and sync, an optional lossy home rebuild that exports every project first, machine-local tiers, the sync remote); `docs/purge-design.md` records the design. The `amem forget` receipt lists same-project capture rows, candidates and work items that contain or overlap the forgotten text, by id and count only. `amem doctor` adds an informational `masked` row (additive `sections.masked` in `amem.doctor/v1`, never raises attention) when forget or prune operations exist.
- **Changed output:** `amem forget --json` printed the single receipt line; it now prints a JSON object `{ forgot, local, nearby }`. Library hosts that do not pass `forgetNearby` keep the single line.
- CI only: the check job timeout is 30 minutes for slow macOS runners (PR #186).

## 0.10.0

- **Behavior change: `amem search` now ranks** (agent-mem#82 G1c, #91). Current-project curated search uses the ranked `store.search` (FTS5/BM25 with tier and recency weights), the same ranking MCP `amem_search` and `amem eval` use. A multi-word query can match notes that contain only some of its words. `--filter` keeps the previous every-word substring filter, newest first. `--history`, `--as-of` and an empty query keep the filter path. `--all-projects` is unchanged and cannot be combined with `--filter`. The command stays person-only, and the refusal happens before the store opens.
- MCP `amem_search` keeps the best-ranked screened matches at real volume (agent-mem#82 G1e, #85). Every matching row is screened by the complete-row policy, then ranked in a query-local SQLite TEMP index before `limit` is taken. Previously only a first page of matches was ranked, so a better match further back could be missed. Expired rows are excluded before the limit. On a real-volume private copy (84,765 capture rows), MCP recall@10 on the 25 frozen AC4 queries rose from 0.72 to 0.84, which meets the #13 AC4 margin (`docs/p5-recall-recheck.md`, #83).
- Faster standalone screening without weaker verdicts (agent-mem#82 G1f, #90):
  - exact fast paths skip the PII patterns when a text has no `@`;
  - the unquoted secret rescan runs only when quote removal changes the text;
  - a necessary-literal probe runs before the deny-path check, over the folded and NFC forms.
  Verdicts are unchanged, as a frozen parity fixture and Unicode cases show.
- Lower MCP memory at real capture volume (agent-mem#86, #99). macOS SQLite's default temp `cache_spill` floor (20,000 pages, about 80 MiB) let dirty pages of the query-local index accumulate past its 2 MiB `cache_size`. The index now spills at its cache target (`PRAGMA temp.cache_spill = 1`). On the real-volume private copy, `amem mcp --smol` peaked at 168.9 MB instead of 271.3 MB, under the R3 200 MB budget, with identical results on all 25 queries. `scripts/measure-mcp-budget.ts` gains an 85K-row `mcp-volume` group, calibrated from aggregate statistics only, that fails at 200 MB.
- Qwen Code (agent-mem#82 G3, #93):
  - `amem setup qwen` registers the MCP server at user scope and adds a bounded SessionEnd ingest hook in `QWEN_HOME/settings.json`. Qwen's own hook controls (`enabled`, `disabled`, notifications) stay user-owned.
  - `amem ingest qwen` reads Qwen Code 0.26.1 native transcripts with a stable cursor and the same screening as the other readers, with no network or native-client call. `QWEN_RUNTIME_DIR` follows a custom `advanced.runtimeOutputDir`. See `docs/qwen-code.md`.
- Jcode, MCP only (agent-mem#82 G3, #94, #98):
  - `amem setup jcode` registers `servers.amem` with `shared: false` in Jcode v0.99.1's global `JCODE_HOME/mcp.json`. It reads the legacy `mcpServers` alias and never writes both spellings. A strict lexical JSON codec leaves unrelated bytes untouched, and undo is conflict-aware.
  - No ingest or hook is installed: saved messages lack a per-message project origin.
  - Supported launch: `JCODE_DISABLE_CLAUDE_MCP=1`, no same-name project override, and a fixed-workspace session.
  - An explicitly set `JCODE_HOME` must be absolute, and this check applies only when jcode is among the targets. See `docs/jcode.md`.
- Antigravity, per repository, MCP only (agent-mem#82 G3, #95, #98):
  - `amem setup agy`, run inside a git repository, writes only `<repo>/.agents/mcp_config.json` (`mcpServers.amem` with an absolute `cwd`), with one private receipt per repository.
  - It never writes the global config, because a global entry would bind every workspace to one project. `setup all` excludes agy.
  - Strict JSON fails closed on JSONC. A git-tracked config is refused, including case aliases, and the preview warns when the file is not ignored.
  - Undo removes `.agents/` only if setup created it and it is still empty. Receipts from older releases restore their configuration without removing a directory.
  - No ingest or hook. See `docs/antigravity.md`.
- Hook capture drains after contention on slow Git (agent-mem#92, #97). The capture worker now overlaps its cold origin and metadata reads (the resolver's existing prefetch, as SessionStart already did). Serial reads could use up the hook deadline before any drain, leaving captured rows pending; nothing was lost. A deterministic regression covers it, and the budget script prints a failure-only drain inventory. Deadlines and budgets are unchanged. Ceiling: native reads slower than the deadline still defer, durably (`docs/92-hook-drain-triage.md`).

## 0.9.1

- Cross-generation prune transport no longer blocks sync (agent-mem#68, #79): split-home sync now transports a verified foreign-generation prune unchanged and keeps it as a private, create-once hold receipt instead of refusing the whole sync, so one shared-row prune from another generation no longer stops every project. Each prune is proved against its own origin generation with the realm's complete public witnesses; invalid or incomplete proof still refuses before publication. A held prune is not applied: its targets can stay visible on the receiving machine, and every successful sync, including a no-op, warns "held, not applied" with up to 10 target entry ids and the remedy (bring the machine to the origin generation, or prune the entry there as the person). Holds never feed the native reducer, index, migration or a generation switch. Full cross-generation application remains a separate ceiling (docs/contracts.md, "Per-shard private sync").
- Recent claude-mem context into capture (agent-mem#13 design G, #76): `amem import claude-mem --capture-days N` also imports the last N days of claude-mem observations and session summaries into the machine-local capture tier, only for claude-mem keys mapped by person-reviewed D2 aliases. Each row is private-span stripped and screened in full by the configured policy and the secret screen before a bounded excerpt is stored; the capture cap and retention apply, the claude-mem database stays byte-unchanged and Chroma vectors are never read. Per-table cursors with stable source receipts make reruns idempotent; widening N later reaches older rows only with `--restart`. Capture rows stay recall context, never curated notes, evidence or synced data. The flag is rejected on other import sources. A fresh capture store now backfills full-text search from `rows.excerpt` directly.
- Faster MCP policy screening (agent-mem#48, #67): deny-name patterns are compiled once and the standalone policy reuses its pure text verdicts per policy instance (at most 512 strings / 64 KiB, cleared when the exported default deny lists change). Screening still runs on complete rows before selection, fails closed and asks a host policy on every call. The MCP budget session on hosted Ubuntu dropped from two 30 s timeouts to 11.5 s.
- Budget scripts tell a slow runner from a regression (agent-mem#71, #74): each budget script records a runner probe (CPU, process spawn, and the median of three durable SQLite writes) before and after its workloads; a wall-time miss on a runner the probe shows slower than twice its hosted baseline re-runs the complete fresh suite once under the same budgets, while a miss on a normal-speed runner, any RSS miss and any correctness failure fail at once. The MCP session keeps its single watchdog-stall retry and now runs with `--smol`, as the shipped binary does. Budgets are unchanged. Measurement-only; nothing ships in the package.
- Installed-package coverage (agent-mem#40 AC1, #13 AC1, #69, #75): the clean-HOME tarball smoke now confirms `amem setup all --apply` through a real terminal prompt, launches and initializes the registered `amem mcp` for Claude Code, Codex, Kimi and Pi, and runs `amem ingest codex|kimi|pi` with a network tripwire and cursor replay. The Codex import test asserts the sources stay byte-unchanged, and every CI budget step now runs after an earlier failure (#70).
- Person-run cutover runbook (agent-mem#13 P5/P6, #73, #77): `docs/p5-cutover.md` lists the claude-mem to amem cutover (including `--capture-days`), its backups and rollback, and the P6 live-week readings. 0.9.0 was not published; this is the first release after 0.8.0.
