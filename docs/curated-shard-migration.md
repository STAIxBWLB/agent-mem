# Curated shard migration contract

This implements agent-mem#15 T2 (AC1, AC2, AC7 and AC8). `amem migrate` and `amem migrate --shards` default to a read-only preview; add `--apply` to write the migration. `--dry-run` remains an alias for preview, while `--resume` and `--deactivate` remain explicit operations. No general agent-marker refusal or TTY gate applies; reader admission and split-marker fences still apply. This document neither publishes a release nor authorizes real-data migration.

- The source may be shared v1 or a populated selected generation G. The journal records sourceGeneration and each segment's source realm and immutable prefix. Shards keep G; original legacy and G bytes are never rewritten.
- `legacy/` and `legacy-main/` retain the separate private/local and public-main birth realms. Generation-owned rows remain in `log/` or `local/`. Original schema, IDs, hashes, placement and own/local/public flags survive replay. Original G remains available through its old read-only bridge.
- Validate every prune against immutable source proofs before output or journal effects. A prune spanning shards becomes one deterministic prune per destination, with a translation receipt naming the source row and its payload hash. Refuse an invalid or incomplete proof; never activate an incomplete migration.
- A project handle reads only that project's curated shard and the user overlay. Merge raw lifecycle facts before deriving visibility, preserving shared recall, shared goals and private-to-shared replacement behaviour. Shared writes and their lifecycle operations belong to user/. Every shard has independent mutation and derived index files; incremental indexing equals rebuild. catalog.db is derived and rebuildable.
- Capture and projects/<key-hash>/work/ stay untouched. Work has its own log/index/lock and is not generation-selected. Capture aliases remain capture-only; this migration does not silently merge curated project identities.
- Cooperating old-layout handles register readers/<pid>-<start-signature>.json leases, renew within 30 seconds, and remove their own valid lease on close. Admission refuses while profile.lock is present. Apply/resume refuse live or unverifiable readers. Confirmed dead leases are removed and their safe filenames/times are journaled. Unannounced older builds cannot be proven absent; unchanged source bytes provide the safety ceiling.
- Resume validates source prefixes and carries later old-format appends, reported by status. Pending resume work marks the split captured before copying; new and already-open shard handles refuse reads/writes until complete activation. Interrupted status reports the captured phase and remaining rows; a no-op active resume keeps the split available. Matching interrupted copied tails can finish append-only; changed or unrelated tails refuse. A machine label change does not change the stable machine identity.
- Before effects, refuse private replacements across projects and shared entries superseded by private entries. Report the latter separately as `shared superseded by private: N`, with entry IDs only. The way out is to un-supersede, or promote the replacement to shared, then rerun. Never copy foreign private text.
- `ponytail:` shared-to-private visibility needs a body-free lifecycle witness and subsequent lifecycle updates. Revisit only if a read-only dry run on a copy of the person's home reports N > 0. This PR adds no witness contract and does not access the live home.

Dry run reports v1, generation-owned, generation-local, prune, translated-prune and refused counts. Acceptance fixtures cover populated G with own/local/pruned entries, immutable source bytes, per-shard rebuild equality, invalid-proof/no-change refusal, both replacement ceilings, partial interruption/resume, reader admission, capture-only initialization and project/user lifecycle continuity.

AC8 uses 20 projects and 200,000 synthetic entries. One-shard open/search measurements and R3 idle/peak RSS are recorded separately from correctness tests; they do not prove an installed runtime, real-home migration or multi-machine sync.

## Host admission and recovery boundaries

There is no registered-host capability registry in this release. Both dry-run and apply output state that hosts must use `openShardStore` before a live-home split; absence of a registry is not evidence of compatibility. Plain `new MemoryStore()` refuses any `shards.json` entry before opening the legacy writer. Published unannounced old-format readers are not changed or rewritten by this rule.

T2 must not ship for agent-hub use until the host integration task switches its memory factory and is installed. The historical agent-hub source example at `2b2d6d2d` opens the core in `src/hub/memory-profile.ts:openProfileMemory` (the `new MemoryStore` at line 157). Its entry points are `src/hub/daemon.ts:startDaemon` (line 912) and `src/cli/memory.ts:commandStores` (line 22). That snapshot also required shard-aware profile binding/receipt integration; it does not establish the current host state or an installed compatible pin.

- Reader registration, renewal, close and the profile-lock claim share `reader-admission.db`, a dedicated short-lived local fence. Data/sync retains `mutation-lock.db`; no reader admission waits on git network work. The profile marker remains held during the switch and refuses new reader registrations. A recognized stale shard-migration profile-lock refusal names `amem migrate --shards --resume`.
- Ordinary generation migration refuses every mode once a split marker exists. It never changes the selector; finish through `amem migrate --shards --resume`.
- Person candidate acceptance opens the selected project shard through `openShardStore`, rechecks current policy and preserves the legacy logs. Candidate-kind constraints and interrupted-acceptance refusals still apply.
- The default durable prune port and CLI select only the project. `amem prune --user` selects the shared/user shard explicitly and preserves its existing wire actor and current-project authorization; the CLI has no general TTY gate. The user-shard library port is `openShardStore({ user: true }).prunePort()`; no implicit merged multi-lock prune is promised.
- Before marking a split captured, inspect every planned copy append and receipt completion. An unrelated native generation tail stays with the original writer; an unsafe touched tail refuses without changing an active split. Empty bridge directories interrupted before their identity metadata can finish initialization; nonempty or unsafe unproven copied bytes refuse with an inspect hint. A matching partial translation receipt completes only by append.
- Apply and resume hold every destination shard's `mutation-lock.db` from a last tail check through the copy (#176). This is a second guard behind reader admission: a live store holds a reader lease and is refused earlier ("legacy reader is live"), so the lock catches only writers that hold no lease. Such a writer mid-append makes the migration wait up to the lock timeout and then refuse with the journal unchanged. The locks are released before each shard index is rebuilt; by then the `captured` phase fences shard writers.
- Dangling immutable lifecycle/suggestion ops are carried as ids-only user metadata and counted separately; later targets retain those operations. Refusal counts distinguish private-cross-project and shared-to-private relations, with ids-only append-only remedies. v1 counts distinguish local and fetched-main realms.
- An interrupted catalog reports curated availability as false and count/time as null; capture receipts remain available and keep the documented cache lag. Its derived schema can be rebuilt without rewriting source logs.

The reviewer recorded the person's read-only dry run on a copy at `1599fdd`: 505 rows across two shards, zero refused, zero shared-superseded-by-private. That observation is bound to that head (hub memory `848f897e`); it does not authorize or prove a live-home migration. The body-free witness ponytail remains, with no witness work in T2.

## Recovering a torn shard tail

A writer that crashes mid-append leaves an unfinished last row: bytes after the file's last newline. Readers never index such a row; they wait for its newline. When the migration has to append to that file, it cannot tell the unfinished row from data, so apply and resume refuse before any journal change and name the file relative to the memory home. The package never cuts those bytes itself. A person recovers:

1. Stop every amem and agent-hub process that uses this memory home.
2. Keep a copy of the named file outside the memory home.
3. Cut the file back to its last newline. The removed bytes are the unfinished row, and the copy keeps them.
4. Run `amem migrate --shards --resume`. It carries the pending rows and returns the split to active.

## Curated shard migration (#15 T2)

Bare `amem migrate --shards` is a preview; `--apply` writes the migration. `amem migrate --shards --apply` moves the curated single home into `projects/<key-hash>/` and `user/` through a resumable generation journal. The original single-home log bytes are never rewritten. A populated selected generation is supported and keeps its generation ID. Each shard keeps private legacy inputs in read-only `legacy/`, public-main inputs in read-only `legacy-main/`, and generation-born rows in its own `log/` and `local/`. It has its own `index-v5.db`, `search.db` and mutation lock; original IDs, hashes, placement and own/local/public provenance are preserved. The source generation bytes stay unchanged. Immutable prune proofs are validated before effects; a multi-shard prune is translated into one deterministic row per shard, with a receipt naming the original row. Existing capture and `work/` directories are not migration inputs and are left untouched. `catalog.db` remains derived and rebuildable, now including curated entry counts and last use. Without active placement, split curated stores sync the opened canonical project and user overlay to separate private-remote refs (`amem/p/<key-hash>` and `amem/u`); unopened projects and machine data are not fetched. Active placement instead syncs the effective home-wide inventory as described below. `--policy-free` remains accepted and never bypasses screening. Original IDs and attribution survive independent generations. See `docs/contracts.md`, "Per-shard private sync", for prune transport and application boundaries.

Before splitting a live home, every installed host must open it through `openShardStore({ project })` or the explicit user shard. Plain `new MemoryStore()` refuses any split marker, including an interrupted split, so it cannot silently keep writing the old layout. No host capability registry currently exists; migration preflight output states that limitation. Do not release T2 for agent-hub use until its memory factory is integrated with `openShardStore` and that host version is installed. Existing unannounced older builds remain the documented unchanged-source ceiling.

Use the same synthetic-home and separate real-data authorization boundary as generation migration:

```sh
AMEM_HOME=/path/to/synthetic-memory amem migrate --shards --dry-run
AMEM_HOME=/path/to/synthetic-memory amem migrate --shards --apply
AMEM_HOME=/path/to/synthetic-memory amem status
# Later old-layout appends are reported by status and carried in idempotently:
AMEM_HOME=/path/to/synthetic-memory amem migrate --resume
```

Every ordinary build that reads the single-home layout holds a cooperating lease in `readers/<pid>-<start-signature>.json`, renewed within 30 seconds and removed on close. Apply and resume refuse a live or unverifiable lease and remove only leases whose pid is confirmed gone. Removed lease filenames and times are recorded in the migration journal and status; registration also refuses while the profile lock is held. Published builds without leases cannot be detected: no process scan proves their absence, and their safety rests only on unchanged legacy bytes. Old-format writers may still append after the split; `amem status` reports those rows and resume carries them into the proper shards. A resume with pending work marks the split incomplete before copying; reads and writes through new or existing shard handles refuse until complete activation. `amem status` then reports the captured phase and pending rows, and `migrate --resume` finishes it idempotently.

Library callers open an already sealed shard directly with `openShardStore({ home, project })` or `openShardStore({ home, user: true })`; these opens do not scan the legacy home or walk the catalog. A project handle reads its own shard plus the user overlay, merging lifecycle metadata before applying visibility; it never reads another project's private text. Shared notes and goals written through a project handle go to `user/`, including their lifecycle operations. Project entries accept only their own project key, while the user shard accepts shared entries. `store.dir` names the selected shard; `store.profile.home` remains the base memory directory. Library callers with a direct base path can use `memoryDir` instead of the historical parent `home` option. Two project shards have independent writer locks, and each incremental index equals its rebuild. `bun scripts/measure-shard-ac8.ts` builds 20 projects and 200,000 entries, poisons the other 19 indexes, and measures open plus ten searches on one shard against the R3 idle/peak RSS limits.

Dry run reports v1, generation-owned/local, prune and translated-prune counts, plus refused relations. A private-to-private replacement across projects refuses before effects. A shared entry superseded by a private entry also refuses: the dry run reports `shared superseded by private: N` and entry IDs only. Un-supersede it, or promote the replacement to shared, then rerun. `ponytail:` supporting that direction requires a body-free lifecycle witness; revisit when a read-only dry run on a copy of the person's home reports a nonzero count, never by probing or migrating the live home here. Private-to-shared replacements remain supported. See [the T2 contract]().

After a split, ordinary generation `amem migrate` modes (including `--deactivate`) refuse without changing the selector. Use `amem migrate --shards --resume` to finish the split. General memory, correction and fail candidates can be accepted into the selected project shard after standalone screening and applicable target checks. Default `prune` selects the current project's shard; use `amem prune --user --cutoff <UTC> --dry-run` and `amem prune --user --apply --plan <file>` for shared/user entries. The current project, reader-admission and split-marker checks remain in force.

A native shard crash tail is left to its original writer's recovery. Migration checks planned copy tails and translation-receipt tails before changing activation; matching copies finish append-only and mismatches give an inspection hint. Dangling lifecycle/suggestion metadata is carried as ids-only user data and counted, so a target arriving later retains its intent. Cross-private replacements have their own ids-only count and the un-supersede/promote-to-shared remedy. During interruption the catalog keeps capture information available while `curatedEntries` is `null` and `curatedAvailable` is `false`; its cached capture counts may still lag.
