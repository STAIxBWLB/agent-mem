# Curated shard migration contract

This implements agent-mem#15 T2 (AC1, AC2, AC7 and AC8). `amem migrate --shards` is person-run and resumable; the existing marker and terminal refusals apply to every mode, including dry run. It neither publishes a release nor authorizes real-data migration.

- The source may be shared v1 or a populated selected generation G. The journal records sourceGeneration and each segment's source realm and immutable prefix. Shards keep G; original legacy and G bytes are never rewritten.
- `legacy/` and `legacy-main/` retain the separate private/local and public-main birth realms. Generation-owned rows remain in `log/` or `local/`. Original schema, IDs, hashes, placement and own/local/public flags survive replay. Original G remains available through its old read-only bridge.
- Validate every prune against immutable source proofs before output or journal effects. A prune spanning shards becomes one deterministic prune per destination, with a translation receipt naming the source row and its payload hash. Refuse an invalid or incomplete proof; never activate an incomplete migration.
- A project handle reads only that project's curated shard and the user overlay. Merge raw lifecycle facts before deriving visibility, preserving shared recall, shared goals and private-to-shared replacement behaviour. Shared writes and their lifecycle operations belong to user/. Every shard has independent mutation and derived index files; incremental indexing equals rebuild. catalog.db is derived and rebuildable.
- Capture and projects/<key-hash>/work/ stay untouched. Work has its own log/index/lock and is not generation-selected. Capture aliases remain capture-only; this migration does not silently merge curated project identities.
- Cooperating old-layout handles register readers/<pid>-<start-signature>.json leases, renew within 30 seconds, and remove their own valid lease on close. Admission refuses while profile.lock is present. Apply/resume refuse live or unverifiable readers. Confirmed dead leases are removed and their safe filenames/times are journaled. Unannounced older builds cannot be proven absent; unchanged source bytes provide the safety ceiling.
- Resume validates source prefixes and carries later old-format appends, reported by status. Pending resume work marks the split captured before copying; new and already-open shard handles refuse reads/writes until complete activation. Interrupted status reports the captured phase and remaining rows; a no-op active resume keeps the split available. Matching interrupted copied tails can finish append-only; changed or unrelated tails refuse. A machine label change does not change the stable machine identity.
- Before effects, refuse private replacements across projects and shared entries superseded by private entries. Report the latter separately as `shared superseded by private: N`, with entry IDs only. The way out is to un-supersede, or promote the replacement to shared, then rerun. Never copy foreign private text.
- `ponytail:` shared-to-private visibility needs a body-free lifecycle witness and subsequent lifecycle updates. Revisit only if a read-only dry run on a copy of the person's home reports N > 0. This PR adds no witness contract and does not access the live home.

Dry run reports v1, generation-owned, generation-local, prune, translated-prune and refused counts. Acceptance fixtures cover populated G with own/local/pruned entries, immutable source bytes, per-shard rebuild equality, invalid-proof/no-change refusal, both replacement ceilings, partial interruption/resume, reader admission, capture-only initialization and project/user lifecycle continuity.

AC8 uses 20 projects and 200,000 synthetic entries. One-shard open/search measurements and R3 idle/peak RSS are recorded separately from correctness tests; they do not prove an installed runtime, real-home migration or multi-machine sync.
