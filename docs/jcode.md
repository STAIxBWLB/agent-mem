# Integration decision

Use the setup-only fallback for this native release. MCP registration is independently supported, but do not expose `amem ingest jcode` or install a capture hook without a verified per-message origin contract. For example, native messages written in project A remain after `set_working_dir(B)`; the persisted root then names B while each old message lacks a cwd. Reading that snapshot from B cannot establish that those messages belong to B. Journal checkpointing and mutable message history also prevent reusing the JSONL byte-offset cursor. A future reader needs a per-message cwd or origin in StoredMessage, plus a snapshot/journal consistency contract, before cursor design.

# Homes and persisted sessions

- `JCODE_HOME` is taken literally as a filesystem path, including relative or empty values. Native code does not expand `~`. With the variable absent, Jcode uses the platform home plus `.jcode`.
- `amem setup jcode` applies a narrower restriction: an explicitly set `JCODE_HOME` must be absolute. Empty values, relative paths and literal `~` are refused, including whitespace-padded relative values such as `" rel "`. Unset uses the default; absolute values retain their literal spelling without trimming. This is an amem setup restriction, not a change to Jcode's native path handling.
- Global MCP config is `<JCODE_HOME>/mcp.json`; lifecycle hooks are in `<JCODE_HOME>/config.toml`. They are separate files.
- Persisted sessions use `<JCODE_HOME>/sessions/<id>.json`. Snapshot and append-journal/checkpoint behavior must not be mistaken for an immutable JSONL transcript.
- **Persisted-history capture is not established by this research.** The current session working directory can change while older messages remain, and stored messages lack their own cwd/origin. Neither the latest session directory nor a hook cwd proves the origin of every historical message. MCP setup can be supported independently; automatic ingest requires a verified per-message origin boundary.
- `JCODE_RUNTIME_DIR` selects separate socket/ephemeral storage and can also redirect durable runtime state; it does not replace the primary session/config home.

# MCP registration

- The global JSON object accepts `servers` and its alias `mcpServers`. Native serialization uses `servers`. amem owns only the `amem` entry under canonical `servers`, reads `mcpServers` as an alias, and must not write both spellings. Preserve unrelated servers and unknown keys byte-for-byte where untouched.
- Existing receipt, idempotency and undo semantics apply; changes to the owned amem entry must conflict rather than be overwritten.
- A stdio entry contains `command`, `args` and `env`; `shared` defaults to true. **The amem entry must set `shared: false`** because amem binds its project from cwd at startup. Shared entries use the daemon-global process pool and inherit daemon cwd; private entries spawn with the manager's captured session project directory. Remote and enable/disable fields must not be overwritten by a stdio registration.
- Use a fixed-workspace session for amem. Changing the agent working directory alone does not rebind existing MCP children. Subscribe/reattach with MCP registration constructs a new manager for its accepted cwd; a manager-level reload instead retains that manager's original project directory. Generic automatic rebinding is not established.
- This release has **no native `jcode mcp add` or `remove` command**. Supported actions are `list`, `test`, `login` and `logout`. Registration therefore edits the owned JSON entry directly; do not invent a native registration command.
- Config loading merges global Jcode entries, live Claude config, then project-local `.jcode/mcp.json`, `.mcp.json` and `.claude/mcp.json`. Later definitions ordinarily override earlier ones, with a special rule retaining existing stdio entries over remote replacements.
- **The private amem binding requires launch-time `JCODE_DISABLE_CLAUDE_MCP=1` when Claude also registers amem.** Live Claude stdio entries replace the entire same-named Jcode entry; an omitted `shared` becomes true again. This commonly applies after setup for both clients. The environment flag suppresses live Claude imports, but same-named project-local entries can still replace the binding. Confirm the effective entry remains `shared: false`; setup changes only its owned Jcode entry and does not alter other client configs or global environment preferences.
- After merging, Jcode expands `${VAR}` and `${VAR:-default}` in configuration strings. Unresolved references remain literal with warnings. Use explicit executable/argument values when recording an amem binding.

# Lifecycle hooks

- `[hooks]` supports `session_start`, `session_end`, `turn_start`, `turn_end` and `post_tool` observers. Each accepts a command string or an ordered array of command strings. `JCODE_HOOK_SESSION_END` and corresponding event variables override config; an empty override disables that event.
- Commands are parsed with shell-style quoting and executed directly, **without a shell**. Shell expansion, pipelines and redirection are not implicit.
- Observers are detached and cannot block Jcode. Their stdin, stdout and stderr are null; there is no JSON stdin payload or native observer timeout. Capture needs its own bounded execution.
- Metadata is passed through `JCODE_HOOK_EVENT`, `JCODE_HOOK_SESSION_ID`, `JCODE_HOOK_CWD`, event-specific variables, and `JCODE_HOOK_PAYLOAD`. The JSON mirror is truncated to 16 KiB and can consequently be incomplete. Prefer the explicit scope variables over assuming the mirror is valid JSON.
- Hook children get `JCODE_HOOKS_DISABLED=1` to prevent recursion. Presence of that variable suppresses dispatch. `session_end` is defined for normal session closure; crash/kill delivery is not guaranteed.
- `pre_tool` is a synchronous gate whose exit code `2` blocks execution; `pre_tool_transform` changes tool inputs and `post_tool_feedback` appends output to results. They are separate capabilities, unsuitable for passive capture. Their timeout fields are explicitly milliseconds; observer hooks have no equivalent field.

# Isolated native verification

- Stage `HOME`, `JCODE_HOME`, `JCODE_RUNTIME_DIR` and cwd. Create an empty staged `mcp.json` before native loading to suppress first-run Codex import.
- Set `JCODE_DISABLE_CLAUDE_MCP=1`, `JCODE_NO_TELEMETRY=1`, `JCODE_HOOKS_DISABLED=1`, `JCODE_NO_AUTO_UPDATE=1` and `JCODE_CHECK_UPDATES=false`; use `--no-update` for startup probes. These apply only to the isolated probe, not the person's installed preferences.
- Disabling Claude import does not disable project-local MCP reads. A private cwd and empty files remain necessary. With `JCODE_HOME` set, external home-file helpers redirect beneath `<JCODE_HOME>/external`.
- `mcp list --json` lists configuration and stored auth state without connecting. `mcp test` connects to a server; it is not required merely to register an entry. Auth/model behavior and capture budgets require separate evidence.
